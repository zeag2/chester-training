## What gets a notification (v1)
| Kind (pref) | When | Who gets it | Text | Opens |
|---|---|---|---|---|
| `friends` | someone sends me a friend request | the person asked | **Erin wants to be friends** · Say yes to see each other's cats. | `#/friends` |
| `treats` | a friend gives my pet a treat | everyone in the pet's household but the giver | **Erin gave Chester a treat** · Say thanks from the Friends tab. | `#/friends` |
| `photos` | a friend posts a photo | friends of anyone in the pet's household (who can already see it), not the household, not the poster | **Erin posted Mochi** · *caption* | `#/feed` |
| `meds` | medicine is due today (a course with doses left, or a next-due date that has come) | everyone in the pet's household, once a day at their reminder hour | **Chester: Revolution due** · 1 of 2 today · until Nov 25 | `#/` (Home's Medicine card) |

Later (not v1): someone pawed my photo (batched: "3 paws on Mochi's photo"), a friend said thanks, "Pet me?" nudges,
vet visit tomorrow, household sync events (Josh, 2026-11-09: "no household notifications beyond sync").

Rules: never more than 20 a day for one person; the same tag within 10 minutes is one notification (and on the phone
a later one with the same tag replaces the earlier); quiet hours 9 PM–8 AM in the person's time zone hold everything
except their medicine reminder (which goes at the hour they picked). Held means dropped, not delayed: these are
"nice to know", and the app shows the same news when it opens.

## How it works
```
friend_requests / friend_treats / pet_photos ──after insert trigger──▶ private.enqueue_push ──▶ push_outbox
pg_cron, every hour at :05 ──▶ send-push {mode:"meds"} ──▶ medsDue per household, at each member's med_hour ──▶ push_outbox
pg_cron, every minute (only if the outbox has unsent rows) ──▶ send-push {mode:"drain"} ──▶ Web Push to each phone
```
- **Schema** (already run, bundle part 3): `push_subscriptions` (one row per phone endpoint; `save_push_subscription`
  moves an endpoint to whoever signed in last). **New** (`20261123000000_push.sql`, idempotent, tested):
  - `push_prefs`: per person, four kind toggles, `tz`, `med_hour` (default 9), quiet hours (21 → 8). Own row only.
  - `push_outbox`: service role only (no grants to anyone signed in). `sent_at`, `tries`.
  - `private.enqueue_push(who, kind, title, body, url, tag)`: skips people with no phone subscribed, honours prefs,
    quiet hours, dedupe and the daily cap. Not callable from the app.
  - Three triggers; each swallows its own errors so a push problem can never block a friend request, treat or photo.
  - `pg_cron` jobs: `paldex-push-drain`, `paldex-push-meds`, `paldex-push-tidy` (drops outbox rows older than 30 days).
    They call the function with `pg_net`, sending a key read from Vault (`push_cron_key`), so no secret is in the SQL.
- **Edge Function `supabase/functions/send-push`** (Deno, deployed by the PM with the Supabase CLI or by Josh from the
  dashboard): checks the `x-cron-key` header against its secret `PUSH_CRON_KEY` (rejects anything else, so the public
  URL can't be used to spam), then:
  - `drain`: takes up to 200 unsent rows (`tries < 3`), sends each to every subscription of that person with
    `npm:web-push@3.6.7` (VAPID; fallback if it doesn't run on Deno: `jsr:@negrel/webpush`), TTL 12 h, the tag as the
    `Topic`. 201 → `sent_at`; 404/410 → delete that subscription (the phone dropped it); other errors → `tries + 1`.
    Payload is JSON `{title, body, url, tag}`; Web Push encrypts it end to end.
  - `meds`: for each person with `meds` on whose local hour is `med_hour`, load their households' cats and `care` rows
    of kind `med` from the last 60 days and run `medsDue` (moved from `src/engine/care.ts` to
    `supabase/functions/_shared/meds.ts` and imported by both, so the app and the server agree; the app's tests run
    on it). One notification per cat ("Chester: Revolution due", or "Chester: 2 medicines due" when there are more), tag
    `meds-<cat>-<day>`.
  - (2026-11-27: the keys now come from Vault through `public.push_secrets()`, see `docs/sharing-setup.md` step 16;
    the env secrets below still win if set.)
  - Secrets: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (`mailto:` Josh's address), `PUSH_CRON_KEY`. Never
    in the repo. The **public** VAPID key also goes in the app build as `VITE_VAPID_PUBLIC_KEY` (it's public by design).
- **Service worker:** today's is generated by `vite-plugin-pwa` (workbox). Add `workbox.importScripts: ['push-sw.js']`
  and a small `public/push-sw.js`: `push` → `showNotification(title, { body, tag, icon: 'icon-192.png', badge,
  data: { url } })`; `notificationclick` → focus an open PalDex window and set its hash to `url`, or open
  `<scope>/#/…`. No switch to `injectManifest` needed.
- **App:**
  - `src/lib/push.ts`: `pushSupported()` (needs `PushManager`; on iPhone only in the Home Screen app, iOS 16.4+),
    `enablePush()` (inside a tap: `Notification.requestPermission()` → `reg.pushManager.subscribe({ userVisibleOnly:
    true, applicationServerKey })` → `save_push_subscription` + upsert `push_prefs` with the phone's
    `Intl.DateTimeFormat().resolvedOptions().timeZone`), `disablePush()` (unsubscribe + delete the row), and a quiet
    re-save on app start when permission is granted (endpoints rotate; it also refreshes `last_seen`).
  - **When to ask** (never on first open; the browser only allows asking from a tap, and a "Block" is hard to undo):
    1. right after sending a friend request ("Get a note when Erin says yes?"),
    2. right after saving a medicine with Repeat or a next-due date ("Remind you at 9 AM when it's due?"),
    3. Settings → App → **Notifications** (always there).
    The ask is a small card in our style (`.card butter`, "Turn on" `.btn2` + "Not now" text button), then the
    browser's own prompt. "Not now" hides that card for 30 days. Signed-out people never see it (no account, nothing
    to send to).
  - **Settings → Notifications** (`.lgroup` + `.switch`, existing components): this phone on/off; Friend requests,
    Treats, Friends' photos, Medicine (with the hour: a `select.in`, 6 AM–10 PM); Quiet hours shown as text ("Quiet
    9 PM–8 AM"). If the browser can't: "On iPhone, add PalDex to your Home Screen first" with a link to the install
    steps. If blocked: "Notifications are blocked for PalDex in your phone's settings."
  - Sign out → `disablePush()` first (so the next person on the phone doesn't get them; the server also moves the
    endpoint on the next sign-in).

## Risks and choices
- **iPhone:** works only from the Home Screen app (iOS 16.4+); Safari tabs can't subscribe. The Settings row says so.
  iOS drops a subscription that shows no notification for a push, so every push shows one (`userVisibleOnly`).
- **Time zones:** stored per person from the phone; the medicine hour is local. Travel: re-saved on each app start.
- **Privacy:** only names and pet names the person can already see; photo captions only to people who can see the
  photo (the same people `can_see_pet` allows). No health details for anyone outside the household. The outbox is
  emptied after 30 days.
- **Cost:** the drain job runs every minute but only calls the function when something is waiting; the medicine job
  runs 24 times a day. Both are well inside Supabase's free tier.
- **Why an outbox, not a Database Webhook straight to the function:** batching and retries, the cap and dedupe in
  one place, and medicine reminders (time-based) use the same path.
